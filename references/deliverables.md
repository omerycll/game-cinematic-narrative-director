# Full production deliverables contract

Output separate linked Markdown files; use stable scene/character/choice IDs to cross-reference:

- `00_README.md`: project premise, scope, versions, canon boundaries, honest completeness status.
- `01_STORY_LAB.md`: >=3 distinct narratives, comparison, rationale, evolution and originality check.
- `02_STORY_BIBLE.md`: protagonist problem, truth, timeline, threat rules, five-act causal synopsis, reveals and earned endings.
- `03_CHARACTERS.md`: every important person's identity, secret, agency, voice, trust matrix, animation/portrait spec.
- `04_BRANCHES.md`: choice matrix, conditions, callbacks, state vars, visual-route differences, duration/replay pathways.
- `05_SCENE_ATLAS.md`: all production scene contracts, hotspots, goals, meaningful interactions, art/audio, unlocks, dialog beats, estimated minutes and scene variants.
- `06_VERTICAL_SLICE_SCRIPT.md`: deep dialogue-by-dialogue opening that could be implemented without guessing.
- `07_PUZZLES.md`: puzzles with sources, steps, failures, hint ladders, alternate routes, checkpoints.
- `08_ART_SOUND_GODOT.md`: unified style guide, color-script, visual storyboard, asset manifest, Godot project hierarchy and localization keys.
- `09_QA.md`: critique, corrections, graph validation output, untested risks and test scenarios.
- `narrative_graph.json`: machine-readable transition graph for branch validation.

If deliverable is not fully written, use explicit `status: treatment` / `status: production-spec` / `status: line-by-line` rather than calling it complete. Aim to finish all scene *production specs* before expanding any one scene to screenplay detail. No imagined final media assets unless user asks for images.
